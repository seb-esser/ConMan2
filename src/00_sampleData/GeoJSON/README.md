# GeoJSON sample data

Test fixtures for the GeoJSON (CityGML-as-GeoJSON) integration of ConMan2.
All files are RFC 7946 GeoJSON `FeatureCollection`s.

ConMan2 needs a persistent identity for the collection (its project id, which plays the role of
the `IfcProject` GlobalId). It reads that from the foreign member `"id"` of the `FeatureCollection`.
If a file has none (e.g. `rfc7946_section1.5_example.geojson`), pass the project id explicitly
(`GeoJsonGraphInterface.geojson_2_graph(..., project_id=...)` or `conman2.py add --project_id ...`).

| Folder | Content | Origin / license | Typical use |
|---|---|---|---|
| `rfc7946/` | Section 1.5 example; all Appendix A geometry examples wrapped into Features; a modified copy of the latter | IETF RFC 7946 (code components, Simplified BSD) | parser round-trip of every geometry type; a quick 2-version diff |
| `citygml_campus/` | `campus_v1` … `campus_v5`: synthetic, CityGML 3.0-inspired campus (Building, BuildingPart, Road, SolitaryVegetationObject, CityFurniture, WaterBody, LandUse, GenericOccupiedSpace) with **controlled changes per version**, see `CHANGELOG.json` | generated by `tools/make_citygml_campus_series.py`, no license restrictions | diff/patch regression tests (semantic, geometric, topological, mixed) |
| `osm_tum_campus/` | real OpenStreetMap buildings around the TUM main campus (Arcisstraße, Munich) at three historic dates (2020-01-01, 2024-01-01, 2026-11-01), 68 → 75 → 78 features incl. two multipolygons with holes | © OpenStreetMap contributors, **ODbL 1.0**; fetched from Overpass API (attic queries), converted by `tools/osm_overpass_to_geojson.py` | realistic diff/patch tests with uncontrolled changes (added/removed buildings, tag edits, re-digitized footprints) |

## What the fixtures exercise

- All seven geometry types: `Point`, `MultiPoint`, `LineString`, `MultiLineString`, `Polygon`
  (with and without holes), `MultiPolygon` (with holes), `GeometryCollection`.
- 2D and 3D positions.
- Feature ids as strings, as numbers (`1001`), and missing ids. Features without an id have no persistent
  identity and are matched by position, like IFC secondary entities.
- `geometry: null` and empty `properties`.
- Nested property objects (`address`), arrays of objects (`genericAttributes`), primitive arrays (`tags`),
  `null` values, booleans, ints and floats.
- Foreign members on the collection (`id`, `name`, `lod`, `bbox`, `snapshot`, `attribution`).
- OSM tag keys with `:` (`addr:city`, `name:ru`), non-ASCII strings.

## Regenerating

```bash
cd src/00_sampleData/GeoJSON/tools
python make_citygml_campus_series.py
# OSM: run the Overpass query in the docstring of osm_overpass_to_geojson.py for a date, then
python osm_overpass_to_geojson.py overpass_<date>.json ../osm_tum_campus/tum_campus_buildings_<date>.geojson \
    --id osm-tum-main-campus-buildings --name "TUM main campus buildings (OSM)" --snapshot <date>
```

## Relation to CityGML 3.0

CityGML 3.0 has no official GeoJSON encoding. Its official JSON encoding is CityJSON 2.0. These files
follow the common "CityGML-in-GeoJSON" practice: the CityGML feature class goes into
`properties.featureType` and the CityGML attributes become feature properties. Relations between
city objects (e.g. `BuildingPart` → `Building`) are only id references in `properties.parent`. See
`src/geojson_graph_interface/README.md` for how ConMan2 maps this onto its graph meta model and what
extensions are proposed for richer CityGML semantics.
